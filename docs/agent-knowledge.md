# Agent 标准知识库工作台

> 开发分支功能，尚未发版。R01/R04残留修复已通过[独立安全复审](reports/agent-knowledge-review.md)，本地自动检查与集成证据见[集成记录](reports/agent-knowledge-integration.md)。现有v0.3.47安装包不包含此工作台；Electron本机GUI、Windows/安装包和真实远端app-llm Key等验证边界仍保留，不代表已具备跨平台发版结论。

## 从原始资料到标准库

工作台把**已同步到本地的原始知识库**整理为独立的标准知识库，提供目录阅读、来源追溯、设计讨论与只读 MCP 查询。

```text
飞书 → 原有同步流程 → 本地原始库（Agent 只读）
                              ↓ 手动构建
                      暂存 → 校验 → 标准库发布
                                      ├─ 目录与正文阅读
                                      ├─ Discuss 讨论
                                      └─ 外部 MCP 查询
```

标准库的文字采用内置的策划文风规则，但仍是模型生成内容，使用前应结合来源核对。工作台不向飞书写入内容，也不把标准库反向覆盖到原始库。

飞书认证与模型认证彼此独立。已有可读的本地原始资料时，讨论、构建不需要重新请求飞书；要获得新的云端内容，仍须先完成原有同步。

## 准备运行时与模型

未安装 pi 不影响原有飞书同步。新工作台需要：

- 外部 Node.js **≥22.19**；开发宿主当前支持 Node 22.19+ 或 24.x。
- `@earendil-works/pi-coding-agent` **≥1.4、<2**。可用 `npm install -g '@earendil-works/pi-coding-agent@^1.4.0'` 安装。
- 能实际调用的模型及对应认证。模型出现在可用列表中，不代表其远程端点一定兼容。

应用使用外部 Node 启动 pi RPC 侧车，不依赖 Electron 内置的旧版 Node，也不因此升级 Electron。

在「设置 → Agent 标准库」检查运行时状态；自动发现失败时，填写 Node 可执行文件路径和 pi 包路径，再点击重新检测。发现过程只读取常见安装目录和 PATH 上 pi 入口的真实路径，不执行 npm。自定义 npm prefix 未在 PATH 暴露 pi 时，需要显式填写 pi 包根或 `dist/cli.js` 路径。

### 输入框切换会话模型

会话输入框底部提供模型与思考强度选择。模型菜单可选择应用提供商下的可用预设，也可主动加载本地 Pi 模型；只展示已启用并配置认证的条目。思考面板提供关闭、最低、低、中、高五档，应用预设须启用思考能力后才能选择强度。

选择按会话保存，刷新页面后仍保留，不修改应用默认模型、其他会话或标准库构建配置。下一次发送会重建不兼容的 Pi 进程并恢复同一会话历史；可以「跟随应用默认」取消独立选择。生成及收尾期间暂不允许切换，须等待结束或停止后操作，避免把新设置误用于正在执行的插话/排队任务。只调整思考强度不重复做模型认证探测。

窄窗口下优先显示消息与输入框，通过顶部会话下拉框切换、新建会话；模式面板作为可关闭的浮层显示，避免三栏挤占正文。

### 默认知识库目录

启动时若本地根目录尚未配置，应用自动创建并保存默认目录。Windows 优先 `D:\飞书知识库`，没有 D 盘或无法写入时尝试 `C:\飞书知识库`；C 盘也不可写时尝试用户 Documents 下的「飞书知识库」。macOS/Linux 默认使用 `~/Documents/飞书知识库`。已有自定义路径保留，不搬动原文档；所有候选均不可写时，可在知识库设置中指定目录。显式设置 `FEISHU_SYNC_HOME` 的隔离部署使用该数据根下的「飞书知识库」。配置文件损坏时不通过自动初始化覆盖原配置。

### 选择模型来源

| 来源 | 使用方式 | 凭据边界 |
|---|---|---|
| 应用内模型（app-llm） | 先在「服务提供商与模型」配置接口协议、Base URL、密钥与模型预设，可点「保存并用于 Agent」直接绑定；也可在运行时设置选择提供商/预设，留空跟随应用默认 | 沿用应用现有 Key 存储约定；交给 pi 时只通过子进程环境，不放入命令行参数 |
| 本机 pi 凭据 | 从 pi 加载的可用模型下拉列表中选择，按提供商分组，选择后自动保存；「刷新模型」重新加载有效配置与认证下的选项 | 由 Pi 原生只读存储解析本地认证，不向界面暴露或复制密钥，不修改通用 Pi 配置；本机配置属于受信运行环境 |

「接口协议」可选择 OpenAI Chat Completions、OpenAI Responses 或 Anthropic Messages。旧配置自动沿用 Chat Completions；每个提供商保存自己的协议和基础地址，同一提供商下的模型预设共用该连接。OpenAI 官方基础地址为 `https://api.openai.com/v1`，兼容网关填写其文档指定的基础地址；Anthropic 官方填写 `https://api.anthropic.com`。Pi 根据协议追加调用路径并处理认证头，应用不会把 Responses/Anthropic 请求转成 Chat Completions。Agent 对话、模型检查和标准库构建共用协议及预设解析，切换协议后已有会话在下一轮按新协议启动。原始文档整理沿用 direct 通道入口，现同样支持这三种协议及流式/非流式输出；提供商、模型代码和输出限制共用解析结果。在应用模型模式下，它跟随 Agent 的应用内提供商/预设；本地 Pi 会话与构建使用只读本机配置，原始文档整理仍使用应用提供商。

应用初始不预置任何提供商、模型或密钥；删除最后一项后可保存为空，后续加载和启动不会重新生成默认预设。历史已有配置仍可读取。「服务提供商与模型」支持新增、编辑、停用和删除提供商及模型预设。提供商保存连接与 API Key；预设保存模型代码、上下文窗口、最大输出和思考能力。可分别设置应用默认提供商/预设，或把当前编辑的提供商默认预设直接用于 Agent。会话、标准库构建和就绪检查共用同一解析链；提供商缺少密钥时不会借用其他提供商的密钥。配置变化后，既有会话在下一轮重新创建 Pi 进程并恢复历史，正在执行的任务沿用启动时的配置。

本地 Pi 列表仅加载有认证的聊天模型，排除未配置凭据的内置名单、非聊天模型与过期 OAuth。只有 auth.json 凭据的提供商也可使用。更新本地 models.json/auth.json 后点击「刷新模型」；配置文件变化会使既有会话在下一轮重建进程。这里的可用表示配置与认证条件满足，端点连通性与账户额度以实际调用结果为准。

应用现有 LLM Key 仍按既有架构明文存于配置文件，请保护数据目录，勿将配置提交到 Git。选择本机 pi 凭据，不等于允许加载任意工具或执行模型生成的命令：侧车只加载应用自己的转发扩展，权限由服务端裁决。

就绪检查不消耗生成额度；构建、会话与运行中追加消息会使用模型额度。端点报错时保留真实错误，不会生成占位“成功”内容。

### 图片理解模型

构建与对话默认只处理文字。需要模型「看懂」源文档中的截图与流程图时，在「设置 → Agent 标准库 → 图片理解」开启开关，并从应用内提供商选择一个支持图片的模型预设；密钥沿用该提供商已保存的 Key，不另存一份。

- 图片理解独立于文本模型：正文仍由会话所选模型处理，图片单独发送到所选图片模型。开启后构建会先理解工作集中的图片再整理正文，命中缓存的图片不重复调用。
- 未开启或单张理解失败时构建照常进行，对应图片在正文中标注「未理解」，构建结果给出张数提示；超出单次构建上限的图片同样如实标注。
- 讨论中可让 Agent 按需读取并理解某张图片，描述结果会被缓存复用。
- 「测试」按钮发送一张内置测试图验证所选模型。图片会发送到所选端点，请确认该提供商可用于处理图片内容。

## 应用插件

在「设置 → Agent 标准库 → 应用插件」按 **Pi原生package** 管理插件。内置“知识库工作台”是一个符合Pi manifest规范的包；对话上下文、Work上下文、构建规则与文风是它的配置项，仍可编辑、启停、恢复默认，也可增加配置项。

点击“添加Pi插件”，输入`npm:@scope/package`、`git:github.com/user/repo`、本地包目录或JS/TS扩展文件的绝对路径。安装、更新、移除调用当前Pi的正式CLI；包manifest、extensions/skills/prompts/themes资源由当前Pi的原生解析器读取。可按整个包启停、更新或移除。本地源码修改后点击“重新加载”。移除本地包只删除本应用的登记，保留源文件。

Pi配置与包缓存位于本应用数据根的`agent/pi-home`。包的启停沿用Pi资源筛选格式，并保存停用前的筛选，重新启用不会扩大原选择范围。运行时只加载本应用登记并启用的资源，不加载通用Pi插件。选择“本机Pi凭据”时，由Pi原生只读认证存储复用通用Pi的认证与模型配置，不复制密钥、也不写通用Pi的设置或模型缓存；过期OAuth凭据需在通用Pi中刷新后再使用。

新增、更新、移除与包级启停要求对话和构建均已停止；空闲Pi进程会回收，下次按新资源启动并恢复会话历史。内置上下文配置保存不影响活跃任务，下次运行使用新快照。多窗口编辑冲突会拒绝旧版本覆盖。

第三方Pi插件以当前用户权限执行代码，可提供自身工具或访问文件与网络；请只添加可信来源。应用自带工具仍保留只读/Workspace约束，目录隔离本身不限制第三方代码能力。依赖Pi终端UI的交互受RPC模式限制，当前扩展对话类UI请求仍返回取消；常规扩展事件、工具和资源可加载。

## 构建、阅读与来源

1. 在原有同步页完成需要的飞书同步，或对已有带同步头的本地资料执行重建索引。
2. 打开「标准库」，首次选择全量构建，确认费用提示。
3. 在右侧「构建」查看进度；发布后通过右侧「目录」选择文档，通过「来源」查看原始内容。选择文档后目录自动收起，正文优先显示。
4. 原始资料有新的本地版本后，手动触发按变更更新；需要重新整理全部资料时使用全量构建。

| 动作/状态 | 含义 |
|---|---|
| 按变更更新 | 比较当前本地源与上次发布快照，处理新增、正文/附件变化和源移除的影响 |
| 全量构建 | 重新覆盖全部当前源；未变资料也属于必须处理的工作集 |
| 来源「当前」 | 对应的**本地源版本**未变化，不承诺已经与飞书云端实时一致 |
| 来源变化/缺失 | 需要先检查本地原始资料，再决定同步、重建索引或重新构建 |
| 取消或发布前失败 | 不切换 CURRENT，上一份完整发布保持可读 |

云端检测把文档标为 changed/error，不会自动排除已有成功本地版本；云端删除观测也不直接冒充本地源删除。sheet 的 CSV 附件参与读取与快照校验，附件损坏或越界不能静默当作完整输入。

构建先写暂存区，通过来源覆盖、路径、内容和快照校验后再发布；模型不能靠一句“完成”绕过校验。界面显示成功以实际发布为准，不以模型回复为准。

构建可并行执行：标准库设置中的「构建并行数」（1–6，默认 2）决定同时处理的单元数。源文档先按关联关系划分为单元，多个模型进程各处理一个单元，最后统一收尾、校验与发布；发布标准与失败影响和单进程一致。并行数受 Agent 进程上限约束，交互会话会保留名额，名额不足时构建排队等待。「构建」面板显示各单元进度、处理进程与图片理解计数。

默认输出目录为数据目录下的 `standard-kb`，通常是 `~/.feishu-sync/standard-kb`；使用 `FEISHU_SYNC_HOME` 时随数据根变化。默认保留最近 3 个发布，构建失败不能删除当前版本。不要手动改写 release 正文、manifest 或 CURRENT；备份时保留完整标准库目录及应用配置/状态库。

切换 Node/pi 配置后，应用仍保护本次运行中已发现的旧安装目录，避免改写尚未退出的旧进程所用代码；重启应用后重新确定保护范围。

## 阅读布局

标准库默认只显示正文和右侧窄工具栏，目录、来源、文档摘要/标签/版本信息和构建进度统一按需展开，不常驻占用正文区域。右侧「目录」支持搜索和选文档，选择后自动收起；「来源」查看文档信息与原始来源；「构建」查看最近运行、日志与取消；「管理」查看当前发布信息，选择源、查看差异/版本和发起更新。

正文采用独立长文排版，默认18px、1.95倍行距；标题分级，段落和章节留出间距，居中限制行宽。点击正文顶部「阅读」可实时调整字号（14–28px）和行距（1.40–2.40倍），也可恢复默认。设置自动保存在当前浏览器或桌面应用本机，刷新、切换文档及下次打开时恢复；窄窗口同样采用所选字号。设置面板和侧栏均默认收起，不保存展开状态。表格与代码字号随正文适度缩放，长代码与宽表格在各自区域横向滚动。

构建运行、完成或失败均不自动展开日志或侧栏。窄窗口展开侧栏时临时覆盖正文边缘，收起后恢复完整阅读面积。

原始文档预览与标准库正文的渲染已按飞书导出的实际形态修复：折叠区块、提示卡、嵌套表格、任务清单勾选框、下划线与上下标等块型可以正常显示；本地图片与附件链接可点击查看或下载；斜体误判、中文段落拼接等显示问题已修正。已有导出文档无需重新同步即可受益。

## 源文档参与范围与变更记录

标准库页右侧「管理 → 源文档」入口按飞书文档父子关系列出已同步的原始文档，缺少父链时按本地目录分组。勾选一个层级会同时选中该层级本身及全部下级文档；部分参与时，父复选框显示半选。支持全选、取消全选、反选，以及展开/收起全部，批量保存覆盖收起的层级，不受旧分页范围限制。搜索时，工具栏批量操作只作用于匹配的文档及匹配层级的下级；单个层级复选框始终作用于其完整子树。排除只保存应用标记，不修改或删除原始文件，也不影响飞书同步和只读讨论；标记在重建索引、重新同步后仍保留，并按原始库根目录隔离。

已被发布版本引用的来源被排除后，会出现在「待更新差异」中，作为待移除的源变化。下次「按变更更新」会删除仅依赖该来源的标准文档；混合来源文档必须依据保留来源重新写出完整正文与sources。恢复参与后，该来源按新增源重新处理。更新进行中暂不允许调整源选择。

本地文件或目录被手动删除后，读取原始库树、标准库源列表和Agent原始库工具时会校正本地派生索引，清理缺失文档、关联表格子索引和不存在的目录映射，刷新相关快照；“重建索引”仍可进行全量校正。兼容仅存旧绝对路径的记录，保留回收站、尚未落盘的云端待同步身份和人工修复队列。根目录离线、不可读、越界路径不作为删除证据。当前源列表只列磁盘仍存在的来源，已删除的旧版本引用在待更新差异和历史版本中追溯。

源列表每行提供「清理」，父层级的清理包括全部下级；也可进入「选择文档清理」，用独立的勾选状态选择多篇、全选或反选，再点击「清理所选」。执行前显示完整清单确认。正文与已登记的CSV附件移至原始库`.trash-bin/sources-*/files/`，对应文档和表格索引一并清理；云端原文不变，下次检测可重新列为待同步。操作失败会回滚已移动文件。回收目录的`cleanup.json`保留文档与表格映射；正文可移回原路径后重建索引，表格附件映射可通过重新同步恢复。标准库通过下一次「按变更更新」消除已删除来源的影响，历史版本保留。构建期间禁止清理源文档。

「待更新差异」比较当前参与源与最近发布快照，展示新增、修改、移除的逐行diff及受影响文档。正文变化、标题或路径变化都进入变化集；更新提示会携带这些diff，模型仍须读取完整当前源，不能凭截断差异补写。无变化时不新建发布。

「变更记录」单独保存每次成功发布的版本、父版本、发布时间、更新说明、源差异和标准文档差异。正文中的构建元数据头不会被当作正文diff。可选择保留版本查看变化，默认保留最近3个版本，沿用standardKb.retainReleases配置；即使父版本被清理，保留版本的已记录diff仍可阅读。本轮提供版本记录与差异查看，不涉及Git分支、远程仓库或回滚操作。

新版本在docs正文目录之外保存源原文快照及changes.json。旧发布如果只有hash、没有历史原文，会明确提示无法还原旧diff，不用当前内容伪造旧版。失败和取消不更新CURRENT，变更记录写入失败也不会发布半成品。

标准文档正文与文档摘要只说明当前规则，须一次成型、自足可读。来源说明、标识、原始路径与构建信息统一放在来源侧栏；正文不附来源段落或脚注，来源只通过独立sources字段追溯。构建写入与发布前均检查这些信息；已有正文需重新完整构建后遵循新规则。变更说明放在独立记录中。生成提示与工具/发布校验会拒绝常见版本头、修订日志和本版/上版对比段落；任意语义性修订叙述仍需结合来源审阅。

## Discuss 与 Work

| 模式 | 允许的操作 | 不允许的操作 |
|---|---|---|
| Discuss（默认） | 检索、阅读标准库和原始库，讨论设计 | 本地写入、命令工具、修改飞书 |
| Work | 在已绑定 Workspace 内读取、创建和修改文件，保留写入审计 | 写原始库/标准库/应用运行资源与凭据目录；shell、命令执行 |

在「对话」新建会话。运行中可选择「插话」影响当前生成，或「排队」作为后续请求；点击停止只表示请求中止生成，不能当作已完成写入或构建的证明。

需要写文件时：

1. 在模式面板选择切换到 Work。
2. 添加一个**独立资料目录**，核对实际路径。
3. 明确点击授权写入后，才向 Agent 提出操作请求。
4. 查看右侧写入记录；完成后可切回 Discuss 撤销写入能力。

只授权愿意交给远程模型处理的资料目录，避免放入密钥或私人文件。文件围栏不是操作系统沙箱，不能约束同账号的外部程序、第三方自动执行器或用户随后主动执行的文件。

会话历史在本地保存；关闭界面不等于删除会话。审计只记录工具、路径与结果等元数据，不记录写入正文。Markdown 外部图片需要显式授权；授权绑定具体 URL，查看另一图片时不会沿用旧授权。

## 任务编排

在对话页右侧「任务」区可开启任务编排（对本会话下一轮生成生效）。开启后，会话中的 Agent 可以把自包含的分析、转换、审校工作派发为后台子任务，同时继续处理对话中的其他问题。

- 子任务分三种角色：分析员（只读分析）、转换员（向 Workspace 指定目录写入）、审校员（只读校对）。任务描述必须自包含：后台子任务看不到当前对话历史，目标、输入材料与期望产出都要写进任务正文。
- 「任务」区显示任务状态、轮次与结果，可展开查看或取消。子任务缺少必要信息而提问时，在任务区直接作答即可继续，作答前任务保持等待。
- 子任务不能再派发任务，也不能执行应用命令；需要构建标准库时，Agent 在对话内发起命令请求并等待批准。
- 关闭任务编排不影响已完成的任务记录。

## 给其他工具连接只读 MCP

在「设置 → Agent 标准库 → 标准库 MCP 连接」复制本机连接片段，粘贴到支持 stdio MCP 的可信客户端。换机器或安装位置后重新复制，不要照搬开发者的绝对路径。

| 工具 | 用途 |
|---|---|
| `search_knowledge` | 搜索已发布文档 |
| `get_knowledge` | 读取已发布正文与来源元数据 |
| `list_knowledge` | 列出已发布文档 |
| `get_release_info` | 查看当前发布信息 |

MCP 不提供 Workspace 写入、任意原始文件读取或会话操作。它直接读取发布目录，不打开 SQLite，也不需要桌面 HTTP Token；未发布时会返回明确错误。连接片段可能使用 Electron 的 Node 模式，也可使用外部 Node ≥20 运行独立 CJS 产物。

MCP 是可信本地进程间连接，不是可直接暴露到公网的 HTTP 服务；不要把“只读”理解成操作系统级隔离。

## 命令行访问

在「设置 → 应用 → 命令行访问」开启后，可以从终端操作本应用。开启时生成独立的命令行令牌，只保存在本机数据目录且仅限本机回环连接使用；关闭后令牌立即失效。「安装命令行工具」会在数据目录的 bin 下生成 `feishu-sync` 命令，按页面提示把该目录加入 PATH 即可，也可直接用完整路径调用。

| 命令 | 用途 |
|---|---|
| `feishu-sync status` | 查看应用、Agent 与知识库状态 |
| `feishu-sync kb build [--full]` | 触发标准库构建（增量 / 全量） |
| `feishu-sync kb builds` | 查看构建记录 |
| `feishu-sync source edit <objToken> …` / `feishu-sync source push <objToken>` | 编辑 / 写回源文档（见下节） |
| `feishu-sync clean orphans --apply --yes` | 清理孤立文件 |
| `feishu-sync auth status` | 查看飞书登录状态 |

全局旗标：`--json` 输出机器可读结果；`--home <数据根>` 指定数据目录；`<命令> --help` 查看参数。破坏性与远端写命令必须带 `--yes`，否则只打印预览并退出。退出码：0 成功、1 业务错误、2 用法错误、3 应用未运行或不可达、4 需要确认。

应用未启动或未开启命令行访问时命令行不可用（退出码 3）；命令行只调用运行中的应用，不会在应用停止时直接改写本地数据。

## 源文档编辑与写回飞书

原始文档预览面板提供「编辑」：修改本地正文后保存，同步头部信息保持不变，编辑前的版本留有备份。仅同步导出的文字文档可编辑；表格等多媒体导出投影不支持本地编辑。

- 编辑后的文档进入「本地已修改」状态；此时正式同步不会覆盖你的修改，而是在同步列表提示先写回或放弃修改。
- 「写回飞书」先显示预览：在云端文档尾部追加新内容，或整篇覆盖云端正文。覆盖会改变云端块结构与评论锚点，需要单独确认；确认前不动云端。
- 云端在编辑期间被他人改过时，写回会提示冲突，由你决定是否覆盖；写回成功后立即拉回云端版本，本地修改状态自动清除。
- 「放弃修改」用备份恢复同步版正文。
- 首次写回前，在「设置 → 飞书认证 → 飞书写入」开启开关并完成一次带写入权限的飞书授权；未开启时只有本地编辑可用。
- 覆盖式写回会把本地整理后的结构写入云端，可从飞书文档历史版本回退。

## 故障与验证范围

- **Node/pi 缺失或版本不支持**：核对路径，重新检测；不要为此升级 Electron。
- **模型未配置或缺认证**：先处理所选来源的认证；可用列表不保证实际请求成功。
- **源在构建中变化**：本轮应失败并保持旧发布，等同步稳定后重试。
- **会话或构建停止**：以最终状态、真实文件/审计及发布指针为准，不把“已请求停止”当成完成。
- **已有原始文件但页面看不到**：检查同步头、索引及归属；不要用伪造映射覆盖陌生文件。

当前真实验证以隔离临时资料、Node 24/pi 1.4、GLM 通道和浏览器为主。Electron 本机最小启动受 dyld 问题阻塞，Windows、安装包、Electron RunAsNode MCP 与全部模型提供商兼容性未验证，不能据浏览器通过直接发版。阶段证据与待修项见 [集成记录](reports/agent-knowledge-integration.md) 和 [设计契约](design/agent-knowledge-design.md)。

Pi就绪状态在标准库、对话和设置之间共享，正常结果复用五分钟，失败结果短暂缓存30秒；后台相同配置的并发检查共用一次探测。修改模型/运行时配置会重新匹配缓存，通用Pi认证或模型文件变化也会在下次查询时失效。点击「检查运行时与模型」可强制重检。RPC启动后立即握手，避免先等待静默超时。


## 源知识库侧栏排序、删除与屏蔽

侧栏拖拽只在同一来源分组、同一父节点内做前后插入，不改变父子层级。展开子树参与整体落点判定，插入线浮在列表上，不撑开行高；中线附近采用小范围滞回，避免鼠标轻微抖动导致落点频繁切换。

在总览的源文档名称上右键，选择「删除文档…」。确认框可选择「同时删除本地源文件」和「移入屏蔽名单」。回收操作包含当前正文、已登记CSV和受管理的XLSX原件/元数据，不删除子文档；移动或元数据提交失败会回滚。取消文件选项时只清本地索引基线，磁盘文件保留，重建索引可重新发现它。

未屏蔽的文档若仍有有效祖先链通向启用中的同步根，删除后立即保留为待同步身份：父链、来源、顺序保留，本地成功基线清空。上级缺失、已删除或所属根停用时，不虚构待同步身份。云端原文与标准库历史版本不随此操作删除；标准库内容在后续「按变更更新」处理。

选择屏蔽后，文档在本地库范围内持久保存屏蔽意图，不进入新检测、缓存差异或媒体核对产生的待同步结果；旧同步请求也会被拒绝。屏蔽仅当前文档，其子文档仍可独立检测。可在「设置 → 知识库与同步 → 同步屏蔽名单」搜索并多选移出；有效上级下保留的身份可再次同步，其他来源可通过后续检测或重新添加恢复。该名单与标准库的「参与构建」标记分别管理。

源知识库侧栏可点击「多选」，使用复选框跨层级选择文档。默认勾选父文档时包含全部子文档（含收起项）；可以取消该选项只选当前文档。支持清空、全选当前筛选结果，以及批量删除、批量移入屏蔽名单；右键已选文档时，菜单显示当前选择的完整数量。全选沿用当前搜索与来源分组，并避免选择界面已隐藏的同步根正文。

多选模式下，普通点击文档行选择该文档并确定连选起点；按住 Shift 点击另一个文档，可选择两者之间当前可见的文档，支持反向连选。macOS 使用 Command、Windows/Linux 使用 Ctrl 点选，添加或取消分散的文档；同时按住 Shift 则追加区间。复选框保留逐项勾选习惯，也支持 Shift 连选。连续范围遵循当前搜索、分组及展开状态；范围内的父文档仍遵循「包含全部子文档」选项。起点已被搜索或折叠隐藏时，以当前点击作为新起点，不带入隐藏的旧区间。

批量操作在执行前向后端生成清单，逐篇展示标题、本地路径和处理结果，并统计待同步、屏蔽、移除索引、本地文件回收、标准文档受影响的数量；回收文件和受影响标准文档均可展开查看。确认框可进一步补全全部下级，也可修改是否回收文件、删除时是否同时屏蔽，修改后重新计算清单。只屏蔽会保留本地文件、表格索引与成功基线。选择父节点及重叠子树时按文档标识去重；可对个别子文档取消勾选，确认清单以实际选择为准。

确认时会复核库根、文档身份/拓扑、屏蔽状态、本地文件状态和标准库版本；有实际影响变化则拒绝旧清单并要求刷新。单纯观测时间刷新不会导致无意义的过期。批量回收和元数据提交作为同一操作执行，一项失败时回滚整批文件和状态；包含同步根本身时按处理后的最终父链判定，不把失去有效上级的文档错误留为待同步。
