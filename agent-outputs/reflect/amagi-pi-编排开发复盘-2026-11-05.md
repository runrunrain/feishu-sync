## 1. 阻塞级问题

### 1.1 递归删除守卫没有授权通道，用户点名的清理最终没有完成 ⭐ P1
- **现象**：用户指令「清理实验数据」，对象是本会话子 Agent 自建的临时目录（约 4.8G）。rm -rf 被 [AMAGI 守卫] 拦截 2 次。第一次拦截后，Leader 做了完整清点（0 个符号链接、0 个硬链接，副本与真实库 diff 为 0 行，逐目录列出大小与文件数）；第二次只删子目录，仍在下一层被拦截。总计 3 次调用，最终只能把命令交给用户手工执行。
- **根因**：插件层只有“阻断”和“mv 保留”两种处置，没有“已清点 + 用户确认”的放行通道。mv 进 amagi-trash 不释放空间，并且已在累积：baize 先前移入的 1.8G 仍在其中。使用者层面：Leader 没有绕过守卫，做法正确。
- **改进方案**：用户逐次确认式放行；对会话自建临时目录做来源登记并降级处理；amagi-trash 提供清空或回收命令；文案给出可直接复制的手工命令。
- **责任归属**：插件
- **证据锚点**：`agent-outputs/reflect/fixtures/rm-guard-block.txt`
- **定级说明**：用户请求未能完成，按“单次即显著损失”归入阻塞级；没有数据风险。

## 2. 摩擦级问题

### 2.1 自动基线测试恒为 unavailable，每次 accept 都要手动豁免
- 现象：8 个 luban 回合的回执全部是 settlement=incomplete，原因都是“项目未声明 verification.testCommand”；accept 时需要手抄 8 次 waivedCheckIds。子 Agent 与 Leader 实际都已跑过测试（隔离 worktree 中 136/136、80/80，全量 3374 通过）。
- 根因：环境缺口与检查失败被同等处理，宿主也不吸收任务内已有的验证证据。本项目主树 SQLite 是 Electron ABI，测试只能在隔离树运行，自动全量测试天然跑不了。
- 改进：环境缺口降为 advisory；支持声明替代验证入口；首次出现时提示配置方法。
- 归属：插件。本项目未在 amagi.json 配置 testCommand，属于使用侧可补齐的部分，但插件的提示与降级成本很低。

### 2.2 只读任务回执的“净变化”混入并行线改动
- 现象：只读的 baize 2a090cf4 回执显示“修改 19、未归因 20”，Leader 额外执行 1 次 git status 才排除误判。diting 08d934ee 的回执里也有“基线已有 36 处”的噪声。
- 根因：共享工作树中有并行写者，摘要头条没有按写面过滤。
- 改进：头条只统计写面命中，外部并发变化单列并降级。归属：插件。

### 2.3 wait 返回 blocked 时不带 QUESTIONS
- 现象：2 次 blocked，wait 返回体都只写“未记录结构化问题”，问题正文要等随后单独到达的通知才能看到。
- 改进：wait 直接内联 QUESTIONS 正文。归属：插件。

## 4. 顺手但可以更好的地方（正向面）

1. **blocked → resume 补答闭环可靠**：2 次 blocked 都给出了真实的设计冲突，例如“Pi 在 --no-approve 之前就读取项目 settings”“SettingsManager 会锁用户目录”，这些是 Leader 写任务书时没预见的事实。补答后续接 2/2 成功，上下文没有丢失，防止了按错误前提硬做。
2. **完成契约检测抓到半成品**：09620f2e 报 done，但缺少 AMAGI:DONE 标记，宿主标注“完成度未自证，勿直接采信”。核实后该轮确实只完成了存储迁移。没有假 done 漏网。
3. **steer 运行中补充信息**：给 baize 设置 deny 后才发现它需要 knowledgeBaseRoot，一次 steer 注入后任务正常完成，不必取消重派。
4. **run_bg 适合 Leader 集成验收**：全量回归（82s）与定向验证（14s）在后台运行，结果附带退出码和日志尾部，可以直接作为验收证据。
5. **待接受提醒**：每个子任务结束后都会提醒尚未 accept 的回合，12 个回合无一漏决策。

可更好：accept 时要手填 waivedCheckIds，与 2.1 同因，已合并到 2.1。

## 6. 一句话总结

编排主链路（派发、blocked 续接、审核回派、验收）在本会话 12 个回合中零假 done、零丢失，表现扎实。主要短板在两处：守卫只能“拦”、没有授权通道，导致用户点名的清理也完成不了；回执检查把环境缺口当作失败，产生恒定噪声。下一步优先修删除守卫的授权通道（P1）。
