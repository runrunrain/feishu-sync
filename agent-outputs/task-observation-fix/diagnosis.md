# 构建任务“已撤销”与未结数异常

复核对象：当前构建 `b_20261104133247_9481ce`。本次读取原生会话、候选区权限账本与检查点进行定位，没有改写正在运行的构建记录。

## 原因

1. 原生 `task_resume` 创建新任务并转移输出分配，旧任务的写入资格以 `superseded_by_resume` 正常撤销。账本中截图对应的旧任务均有后继任务。前端只按 epoch/代次区分历史，未排除同代次的 revoked 父任务，导致旧任务仍计入“当前计划”和“已派发未结任务”，并以红色“已撤销”加“待完成”展示。
2. 当前 amagi 通过 Pi 原生 `role=custom`、`customType=amagi:task-completion`、字符串 content 和 `details.taskId` 发送完成通知。宿主只从文本块数组或 message.text 提取通知，漏掉了字符串 content，完成状态没有转发给监督器。
3. 派发回执明确有 `details.execution=queued`，监督器却把创建一律记为 running；因此等待准入的任务也显示为已派发运行。

## 修复

- 读取原生自定义完成通知，并核对完整 taskId、短句柄及角色；兼容旧版用户消息和原生异常收尾通知。只认通知首行，不从助手正文、引用段或其它 customType 猜测状态。
- 把原生派发回执中的 queued/running 传到监督器。
- 宿主在首次读取会话时，补读本绑定的原生持久完成通知，恢复旧版漏记的执行观测；不修改原生历史、不重新授权 revoked 任务、不改变输出分配。监督器通过宿主回调完成恢复，历史 DTO 在服务层同样补读。
- revoked 父任务只作历史；存在后继任务时显示“已续接”和后继 ID，不再显示“待完成”，不再计入当前计划/未结数。

## 验证

- 26 项前端进度测试、20 项权限账本测试、27 项监督集成测试、9 项原生消息/恢复/真实宿主转换测试通过，共 82 项。
- 类型检查、变更文件 ESLint、前后端及 Electron 构建通过。
- `live-replay.json` 保存了只读重放结果：当时检查点有 25 个任务，旧显示有 25 个未结；原生通知可恢复 18 个 done，4 个旧任务属于已续接历史，当前观测未结为 6。权限状态核对未变。该数字属于该检查点与日志读取时刻，运行中会继续变化。

修复版安装至应用目录时保留当前构建进程。正在运行的旧后端需在构建结束并重启应用后加载修复；首次加载会补齐已有完成通知。
