# 成果协议（写作/审查/调研共用）

成果的真相在应用侧：候选区草稿、对象与证据登记、审查回执、交接记录。你的任务回复只携带引用与结论。

## 提交语义

- **幂等**：同键（任务 + 操作）同载荷返回原回执；同键异载荷被拒绝。回执丢失可安全重放——用同一操作 ID 重试，不要换 ID 重复提交。
- **版本**：每次接受返回新 revision；已落盘未回执时允许安全重放，不重复计入。
- **错误结构化**：错误包含字段、现值与可用定位——按定位修正后重试，不盲试。

## 交接记录（handoff）

子任务完成或受阻时经 `build_handoff_submit` 提交交接记录（`operationId` 幂等；`summary` 必填），字段：

- `artifactRefs`：成果引用（文档路径或路径@revision、对象 ID、审查报告 ID）。
- `sourceScope`：本次覆盖的来源（objToken 列表）。
- `openIssues`：未解决问题（含依赖与影响面描述）。
- `nextInfo`：下一步所需信息或建议（调用示例见 `mcp-examples.md`）。

正文留在应用候选区；交接只携带可回读引用与必要摘要。

## 发布与接受

- 应用接受成果 ≠ amagi 接受任务：Leader 在成果取得应用回执后才在 amagi 中接受任务；两边状态由 Leader 对齐，你不直接操作 amagi。
- 最终成功以应用返回的发布或候选接受结果为准（由 Leader 申请）；你的任务终态只是运行结束。

## 调研子任务（baize）补充

只读取证：提交交接记录（发现、证据位置、与既有内容的关系），不提交正文或对象。
